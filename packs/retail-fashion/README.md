# Retail fashion pack

Domain knowledge for fashion retail ideas (apparel, footwear, accessories; stores, online or both). It is public, generic knowledge with fictional examples. It holds no company's real figures.

## Who reads it

- The problem-framing lens reads `drivers.md` and `traps.md` to ask sharper questions about where the pain comes from, and to catch a wrongly read cause.
- The outcome lens reads `metrics.md` to propose a metric with a plain definition and a formula, and to check that baseline and target use the same definition.
- The challenge lens reads `traps.md` and `promotions.md` to test whether a claimed result survives seasonality, weather, channel shift or discount effects.
- The solution-sketch lens reads `drivers.md` and `promotions.md` for journeys and edge cases.
- `questions.md` holds example questions per lens in Vietnamese. Treat them as starting points: adapt to the user's own words and shops, and send them through the ask protocol. Never read them out as a script.

## Rules for using the pack

1. The pack suggests; the user's answers decide. Never present a pack figure as the user's own.
2. Use a metric only to fill an open coverage gap, and confirm the definition with the user before recording it (a "sell-through" in one chain may be counted over a different period than in another).
3. When you use a formula, ask for the inputs and record each with source and period. Never fill an input from this pack.
4. Explain a term in one plain sentence the first time (see the writing rules). The definitions here are written to be reused that way.
5. A trap is a hypothesis to test with a question, not a verdict. Ask for the evidence that rules the trap out.
6. Vietnamese examples use "bạn" for the user and shop vocabulary the user already uses (tồn kho, size, đợt hàng mới).
